## 1. P1 确认项

### P1-1　Repair 状态下任意“保存”会用默认配置覆盖损坏配置

- 位置：`rust/src/gui.rs:518-525`、`1959-1966`、`2081-2093`；`rust/src/config.rs:349-356`
- 确认：`ConfigStore::recovery` 把 `config` 设为 `Config::default()`；`save()` 无条件写入。
  GUI 的 APK 保存、依赖路径保存、外勤开关都调用 `save()`，不检查 `recovery_error`。
- 影响：进入 Repair 后点击任一保存，损坏文件被默认值替换（有备份，但无提示，等同静默丢失原设置）。
- 建议：`recovery_error.is_some()` 时禁止 `save()`，要求显式“修复/覆盖”确认。

### P1-2　数据目录迁移不持久，重启会退回源目录

- 位置：`rust/src/config.rs:419-460`；`rust/src/gui.rs:408-430`
- 确认：`migrate_to_root` 复制数据并返回新 store，但不删除/改名源 `config.toml`，也不写持久指针。
  重启后 loader 仍优先命中源便携配置。
- 影响：迁移“成功”后新日志/截图 split 到旧目录，功能未闭环。
- 建议：持久化选定的 root 并优先读取；该变更需要 ADR（见 ADR-0003）。

### P1-3　相对 `--config` 被原样写入计划任务

- 位置：`rust/src/main.rs:1092-1094`、`1143-1153`
- 确认：`build_task_command_line` 使用原始 CLI 值，不解析为绝对路径。任务计划程序无工作目录，
  `--config config.toml` 会在 `System32` 下解析；loader 还可能在那里新建默认配置和目录。
- 影响：任务每天失败或使用了错误配置。
- 建议：始终写入 `store.path` 的绝对路径。

### P1-4　发布 workflow 不绑定 tag 名、Cargo 版本或 tag 目标

- 位置：`.github/workflows/release.yml:3-10`、`.github/workflows/ci.yml:44-63`
- 确认：workflow 内无 `git describe --exact-match`、无 `github.ref` 校验。
- 影响：可发布版本号与 tag 不一致的产物；`workflow_dispatch` 可在任意分支运行。
- 建议：断言 `git describe --tags --exact-match HEAD == v$version`，并限制 dispatch 的 ref。

### P1-5　已发布的 v0.3.1 不含本次修复

- 确认：`v0.3.1 = a955d0a`，计划任务引号与成功日期修复在 `90d086a`。
- 影响：下载 v0.3.1 的用户仍会遇到 `2147942487` 和 `success_date_unknown`；文档未披露。
- 建议：CI 通过后发布 `v0.3.2`，或在 v0.3.1 release notes 标注已知问题。

### P1-6　成功日期提取不再按目标 package 作用域（`90d086a` 回归）

- 位置：`rust/src/main.rs:2325-2327`、`2371`、`1881-1938`
- 确认：改为传入原始 XML 后，`extract_hierarchy_date` 不再过滤 `package`；旧实现使用
  `scoped_text`（仅目标包节点）。
- 影响：状态栏/外部窗口/隐藏节点中的日期会进入 `all_dates`，导致真实成功被报
  `success_date_unknown`；也可能被锚点接受为成功日期。
- 建议：解析时按 `package` 过滤，并补外部日期测试。

### P1-7　空依赖路径可清除 Setup 门禁

- 位置：`rust/src/gui.rs:885-898`、`918-926`；`rust/src/config.rs:182-201`
- 确认：`validate()` 不检查 `ldconsole_path`/`adb_path`；保存或 reload 成功后无条件
  `setup_required=false`。
- 影响：未配置依赖即可进入工作台；运行时仍 fail-closed，但门禁被绕过。
- 建议：Setup 保存路径强制非空；reload 后按同一谓词重算。

### P1-8　GUI live 确认未快照目标，配置/实例变化后仍可确认

- 位置：`rust/src/gui.rs:1103`、`1473-1507`
- 确认：`pending_live_run` 只是 bool；确认时读取当前 `store` 与 `selected_instance_index`。
  重置默认、切换配置、迁移都不会清除它。
- 影响：用户确认的可能是 A 配置/A 实例，实际执行的是 B。
- 建议：打开对话框时快照 `(root, path, instance, all_instances)`，确认时校验未变化。

### P1-9　BACK 被吞回退与冻结安全契约冲突，且无 ADR

- 位置：`rust/src/main.rs:3388-3394`、`3556-3616`；`docs/CHECKIN_SAFETY.md:37-45`
- 确认：文档要求“可读但非目录页 → `stale_page_refresh_failed` 并停止”；代码现在会在仍为
  签到页时继续。回退只写事件，`result.json` 可通过
  `page_refresh_attempted=true` + `page_refresh_confirmed=false` 识别。
- 影响：行为与冻结契约不一致；需要 ADR（见 ADR-0002）。
- 建议：补 ADR，并更新安全文档。
