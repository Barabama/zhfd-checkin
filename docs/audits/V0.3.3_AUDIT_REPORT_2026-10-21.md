## 2. 用户关注点一：dry-run 不能一键登录

### 2.1 当前行为（已确认）

```text
run --dry-run
  → auto_login_if_required
  → authorize_auto_login(DryRun) = Ready
  → 只写 auto_login_ready=true，不调用 perform_one_click_login
  → locate_or_navigate 仍看到 Login
  → error_code=login_required，exit=3
```

证据：

- [domain.rs:272-275](../../rust/src/domain.rs#L272-L275)：`DryRun => Ready`，`Live => Authorized`。
- [auto_login.rs:178-198](../../rust/src/auto_login.rs#L178-L198)：`Ready` 分支只设置 `auto_login_ready` 并返回，不点击。
- [main.rs:2078-2096](../../rust/src/main.rs#L2078-L2096)：随后进入 `locate_or_navigate`。
- [main.rs:2110-2121](../../rust/src/main.rs#L2110-L2121)：Login 路由写入 `login_required`。
- 2026-10-21 00:58 的本机 dry-run 日志：`auto_login_ready=true`、`auto_login_attempted=false`、`auto_login_tap_count=0`、`clicked=false`、`error_code=login_required`。

### 2.2 这是不是“设计缺陷”

**是产品级设计缺口，但不是实现 bug。** 它来自冻结的安全不变量“dry-run 永不点击”，该不变量写在 [CLAUDE.md:103](../../CLAUDE.md#L103) 与 [CHECKIN_SAFETY.md:25](../CHECKIN_SAFETY.md#L25)。问题在于一键登录属于**会话建立（session setup）**，不是签到动作；把它和签到点击一起禁止，会导致：

1. 会话过期后 dry-run 永远只能停在 `login_required`，无法继续观察签到页；
2. 唯一的登录 tap 路径是 `run --live --confirm`，而该命令在窗口内会继续执行真实签到点击，不是“只登录”；
3. 新预设（1080x1920@480、720x1280@320、540x960@240）未标定，live 在登录代码之前就被 `uncalibrated_profile` 拦截（见 SAFE-02），因此这些预设上**没有任何可执行的登录验证路径**。

### 2.3 建议方案

**首选：新增独立的 login-only 动作，不放宽 dry-run。**

```text
zhfd-checkin login --instance-index N --confirm-login
```

要求：

- `runtime.allow_auto_login` + `runtime.accept_login_terms`；
- 自己的显式 `--confirm-login`（不与 `--live --confirm` 复用）；
- 目标前台、`route=Login`、无外部窗口；
- 最多一次协议复选框点击 + 一次登录点击；完成后立即退出；
- **不进入** `locate_or_navigate`、不调用 `guarded_tap`、不执行签到；
- 不要求 Profile 已标定（登录坐标来自 hierarchy bounds）；
- `result.clicked=false`，`auto_login_tap_count` 记录登录点击；
- GUI 增加“测试一键登录（仅登录）”按钮，确认框明确写出“将点击登录页，不会签到”。

这样 `run --dry-run` 仍保持零 tap，`run --live` 仍只负责签到；需要先登录时，用户显式执行 login-only，再运行 dry-run 观察。

**次选（不推荐）**：给 `run --dry-run` 增加 `--auto-login` 和独立 `--confirm-login`，登录成功后立即结束 run，不进入签到导航。仍需要 ADR，且“dry-run 仍会 tap”会造成文档/审计歧义。

无论哪种方案，都需要新增 ADR（建议 ADR-0005）明确“签到动作 vs 会话建立动作”，并修订 ADR-0004 第 6 条与 CLAUDE/CHECKIN_SAFETY 的 dry-run 表述。

## 3. 用户关注点二：GUI「期望账号」与个人信息

### 3.1 是否存在“硬编码默认账号”

**没有发现硬编码或发布包内置的默认账号。**

- [config.rs:50](../../rust/src/config.rs#L50)：`DEFAULT_CONFIG` 中 `auto_login_account = ""`。
- [config.rs:165](../../rust/src/config.rs#L165)：字段默认空字符串。
- `git log --all -S'<真实账号>'` 无结果；tracked 文件中没有真实账号。
- release 包只包含两个 EXE 与 README，不含 `config.toml`（[package_release.ps1:60-84](../../scripts/package_release.ps1#L60-L84)）。
- 测试使用 `000000000` 脱敏值。

**GUI 中看到的账号来自本机持久化配置**：启动时 `gui.rs:2298` 读取 `store.config.runtime.auto_login_account`，填入文本框。本机当前 `rust/target/release/config.toml` 已为空，但审计发现：

- `rust/target/release/backups/` 下 5 个备份仍包含非空 9 位数字账号（已脱敏确认）；
- `debug/instance2-home.xml` 含另一个真实账号（登录页 hierarchy）；
- 本机 2026-10-21 00:23 的 live 验证曾把真实账号写入便携配置，GUI 随后会显示该值。

因此用户看到的“默认账号名”是**本机配置/历史备份的持久化值**，不是源码默认值；但下面的泄露路径仍然成立。

### 3.3 建议修复

1. **诊断报告（P1）**：序列化前清空/掩码 `auto_login_account`，增加回归测试（设置假账号，断言报告不含该值）；同步更新文档。
2. **GUI（P2）**：输入框默认掩码（仅显示末 2-4 位或 `<已配置>`），提供“显示/替换/清除”；“当前配置内容”对 `auto_login_account` 与 `bark_url` 掩码；保存改为显式按钮，避免 focus-loss 反复写备份。
3. **备份（P2）**：备份时序列化脱敏副本，或加密；清除账号时提供“清除并清理备份”；不要每次失焦都写备份。
4. **`.gitignore`（P2）**：增加 `config.toml`、`**/config.toml`、`config.toml.bak.*`、`backups/`、`**/backups/`；增加 CI/pre-commit 扫描 tracked 文件中的非空 `auto_login_account`。
5. **`config show`（P3）**：默认脱敏，提供显式 `--show-secrets`。
6. **本地证据（P3）**：删除/迁移 `debug/`、`captures/` 中的旧 hierarchy/截图；`.env` 若为真实远程凭据，应轮换（需用户批准）。

### 3.4 账号绑定建议

当前 `auto_login_account` 可留空；为空时 `authorize_auto_login` 跳过账号匹配（[domain.rs:267-271](../../rust/src/domain.rs#L267-L271)）。既然产品上已选择“绑定期望账号”，建议在 GUI 开启 `allow_auto_login` 时要求填写或至少显示强警告；否则一键登录可能进入 App 记住的任意账号。

## 4. 其他安全/证据问题

### SAFE-01（P2）登录点击发生在窗口检查之前，且 live 确认未披露

- [main.rs:2073-2087](../../rust/src/main.rs#L2073-L2087) 在导航前执行 auto-login；签到窗口检查在 [main.rs:2211-2226](../../rust/src/main.rs#L2211-L2226)。
- 00:23 的 live 验证就在窗口外完成了登录。
- [gui.rs:114-119](../../rust/src/gui.rs#L114-L119) 的 `LiveRunIntent` 只快照 config path/root/index/all-instances，不含 `allow_auto_login`/`accept_login_terms`；[gui.rs:1622-1630](../../rust/src/gui.rs#L1622-L1630) 只写“将执行真实签到点击”，未说明会点登录页。
- 建议：ADR 明确“登录 tap 不受签到窗口约束”或改为受窗口约束；live 确认框增加“将点击登录页（可能在窗口外）”一行，并把两个 auto-login 开关纳入快照。

### SAFE-02（P2）未标定 Profile 在登录前拦截 live

- [main.rs:2039-2047](../../rust/src/main.rs#L2039-L2047) 在 `auto_login_if_required` 之前返回 `uncalibrated_profile`。
- 登录坐标来自 hierarchy bounds，不需要 Profile 几何；但新预设 1080x1920@480、720x1280@320、540x960@240 未标定，因此 live 登录无法运行。
- 建议：login-only 动作不要求 `calibrated`；签到 live 仍要求。把 `profile_calibrated` 纳入 `AutoLoginEvidence` 或明确 login-only 的独立策略，避免未来调用顺序变化绕过门禁。

### SAFE-03（P2）事件级 `clicked:true` 语义冲突

- [auto_login.rs:263,331,380,392,414](../../rust/src/auto_login.rs#L263) 对协议/登录点击写 `clicked:true`。
- `result.clicked` 仍只表示签到点击（正确），但事件消费者可能把登录 tap 计为签到 tap。
- 建议：登录事件改用 `login_tapped`/`consent_tapped`/`tap_kind`，保留 `clicked` 给签到；加测试断言登录事件不含 `clicked:true`。

### EVID-01（P2）live 证据早于最终代码

- [AUTO_LOGIN_DESIGN:329-330](../design/AUTO_LOGIN_DESIGN_2026-10-21.md#L329-L330) 记录：唯一 live 登录证据之后又加入了“pre-tap 使用最新复选框 bounds”和“任意 route 检测登录弹窗”，未再现场复测。
- [STATUS.md:53,65](../STATUS.md#L53) 却把设备验证写成“是”，没有这个 caveat。
- 建议：STATUS/release notes 补充；“login-only”实现后，用 tag 构建重新做一次现场登录验证。

### DRY-02（P2）dry-run 探针要求协议授权且丢失拒绝原因

- [domain.rs:263-271](../../rust/src/domain.rs#L263-L271) 在 dry-run 也要求 `accept_login_terms=true`，否则 `auto_login_ready=false`。
- [auto_login.rs:188-198](../../rust/src/auto_login.rs#L188-L198) 的 dry-run refusal 只写事件，不写 `error_code`；[main.rs:2110-2121](../../rust/src/main.rs#L2110-L2121) 统一覆盖为 `login_required`。
- 建议：dry-run 只做观察，不要求法律同意开关；把 `auto_login_blocked_by` 或 refusal code 保留到 result（或至少 error_stage/recovery）。

## 6. 正面结论

- 153 个测试、`cargo fmt`、`cargo clippy -D warnings`、CI/release 均通过。
- 登录门禁顺序正确：开关 → route → overlay → 按钮唯一 → 协议节点 → 协议授权 → 账号存在/匹配 → dry-run/live。
- 一次运行最多一次登录点击；点击前重新观测；协议复选框有视觉确认；失败 fail-closed。
- `result.json`/`events.jsonl` 只记录账号布尔值，不记录账号原文；登录截图是唯一明文例外。
- 发布包不含 config/logs/账号；源码无硬编码默认账号；git 历史无账号值。
- 预设表 8 项与 `PROFILES` 精确对应；改 DPI 的三个 Profile 保持 `calibrated=false`；legacy `900x1600@240` 保留并标注。
