# ADR-0004：登录页「一键登录」显式 opt-in

- 状态：**已接受并实现（v0.3.3）**；现场完整签到 live 与独立审计仍未完成
- 提议日期：2026-10-21
- 分支：`feat/auto-login`
- 影响决策：`docs/V0.3.0_DECISIONS.md`「实施边界」；`docs/V0.3.0_FIRST_RUN_AND_RECOVERY_REQUIREMENTS.md` §10
- 设计稿：[AUTO_LOGIN_DESIGN_2026-10-21.md](../design/AUTO_LOGIN_DESIGN_2026-10-21.md)

## 背景

v0.3.0 的冻结决策明确要求「不自动登录、不录入凭据、不自动同意协议」。
2026-10-21 现场核对发现：三个 LDPlayer 实例中 index 0 停留在登录页，index 1/2 已登录；
登录页只提供「一键登录」「其他账户登录」「点击注册」，没有可直接进入签到页的路径。
现有程序正确识别 `PageRoute::Login`，但只能以 `login_required` 停止，用户必须手动登录。

现场 hierarchy（已脱敏）显示「一键登录」使用 App 记住的「上次使用过的账号」，
不需要输入账号、密码或验证码。这与冻结决策所防范的「录入凭据」不是同一类动作，
但仍属于「程序代用户发起登录」，且勾选协议属于代用户作出同意，因此必须走 ADR。

## 决策（提议）

1. 新增 `runtime.allow_auto_login`（默认 `false`）。关闭时行为与 v0.3.2 完全一致。
2. 新增 `runtime.accept_login_terms`（默认 `false`）。只有它为 `true` 时才允许程序
   代勾选《用户协议》《隐私协议》；`allow_auto_login` 本身不隐含同意。
3. 只支持「一键登录」：
   - 不输入账号、密码、验证码；
   - 不处理「其他账户登录」；
   - 不保存任何凭据到 config、日志、事件或环境变量。
4. 登录动作仍经过 `--live --confirm`、目标包前台、无外部窗口、route=Login、
   节点唯一、账号匹配（可选）、复选框视觉确认、点击前二次观测等门禁。
5. 一次运行最多一次登录点击；点击后只观察，不重试、不循环。
6. dry-run 永不点击；只输出 `auto_login_ready`。
7. 失败一律 fail-closed，并返回稳定的 `auto_login_*` 错误码。
8. `RunResult` 新增 `auto_login_*` 字段；**不记录账号原值**，只记录是否匹配。
9. GUI 提供两个高风险开关与红色警告文案；默认关闭。
10. 本 ADR 只放宽「登录页的一键登录」，不放宽签到点击门禁、不改变
    `Checkin + Ordinary/FieldWork` 授权、不改变成功判定。

## 影响

- 默认行为不变，旧配置无需迁移。
- 操作员必须同时打开两个开关，才会发生登录点击。
- 代勾选协议具有法律同意含义，风险由操作员显式承担；文档与 GUI 必须明确提示。
- 若 App 的一键登录在模拟器中不可用（例如依赖运营商能力），功能将表现为
  `auto_login_timeout`，不会回退到密码登录。
- 账号配置是全局的；多实例使用不同账号的场景不在本版本范围。
- 运行中途会话失效仍以 `login_required` 停止，不在本版本范围。

## 兼容性与回滚

- 新字段全部 `#[serde(default)]`；旧 `result.json` 仍可读取。
- `schema_version` 保持 3：新增字段均为可选，旧消费者可忽略；不做破坏性升版。
- 回滚：把 `runtime.allow_auto_login` 设为 `false`，立即恢复 v0.3.2 行为。

## 批准条件

用户已于 2026-10-21 明确确认：

1. 接受「程序在登录页代勾选《用户协议》《隐私协议》」；
2. 只支持一键登录，不做账号密码/SMS；
3. 配置期望账号并在登录前校验；
4. 允许在 index 0 上做一次 live 登录验证。
